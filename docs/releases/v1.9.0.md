# bstrings v1.9.0

bstrings v1.9.0 is an offline-first Windows forensic strings toolkit. The core
scanner works by itself; the complete kit adds file routing, decoded-string
recovery, OCR, language detection, local translation, all validated patterns,
and provenance reporting behind the same `bstrings.exe` interface.

## Download

- [Core Windows x64 ZIP](https://github.com/Donovoi/bstrings/releases/download/v1.9.0/bstrings-win-x64.zip)
- [SHA-256 checksum list](https://github.com/Donovoi/bstrings/releases/download/v1.9.0/SHA256SUMS.txt)
- [Quality offline-profile manifest](https://github.com/Donovoi/bstrings/releases/download/v1.9.0/bundle-packs-quality.json)
- [All v1.9.0 assets and smaller profiles](https://github.com/Donovoi/bstrings/releases/tag/v1.9.0)

Use assets from one release only. The core ZIP is enough for native extraction
and pattern matching. Download the quality manifest as well if you want every
offline feature.

## Verify and run the core scanner

Verify the ZIP before extracting it:

```powershell
$rows = @(Select-String -LiteralPath .\SHA256SUMS.txt `
  -Pattern '^[0-9a-f]{64}  bstrings-win-x64\.zip$')
if ($rows.Count -ne 1) { throw 'Missing or duplicate core checksum' }
$expected = $rows[0].Line.Substring(0, 64)
$actual = (Get-FileHash -LiteralPath .\bstrings-win-x64.zip -Algorithm SHA256).Hash.ToLowerInvariant()
if ($actual -ne $expected) { throw 'bstrings-win-x64.zip SHA-256 mismatch' }
'Core ZIP verified'
```

Extract the ZIP with Windows Explorer. From the extracted directory:

```powershell
.\bstrings.exe -f D:\evidence\image.raw --lr all --ro --off -s -o D:\results\hits.csv
```

## Install every offline feature

On a connected staging computer, put the quality manifest beside the extracted
core and run:

```powershell
.\bstrings.exe bundle acquire `
  --manifest .\bundle-packs-quality.json `
  --output C:\Tools\bstrings-quality

C:\Tools\bstrings-quality\bstrings.exe bundle verify
C:\Tools\bstrings-quality\bstrings.exe analyze -d D:\carved --full -o D:\results\full
```

`bundle acquire` resumes downloads, verifies exact byte lengths and SHA-256
values, assembles the complete kit, and verifies its strict manifest. Transfer
the entire output directory to an air-gapped workstation and run
`bstrings.exe bundle verify` again before examination. The analysis pipeline
does not download anything.

## Choose an offline profile

Every profile includes the same scanner, [Magika](https://github.com/google/magika),
[FLOSS](https://github.com/mandiant/flare-floss), OCR, reporting, and local
translation runtime. Only the translation model changes.

| Profile | Translation model | Model size | Best for |
| --- | --- | ---: | --- |
| `quality` | Hy-MT2-7B Q8_0 | 7,981,928,896 bytes | Strongest measured local translation; default |
| `balanced` | Hy-MT2-1.8B Q8_0 | 1,908,528,192 bytes | Smaller transfer and memory footprint |
| `compact` | Hy-MT2-1.8B Q4_K_M | 1,133,080,448 bytes | Smallest and fastest reviewed profile |

Choose another `bundle-packs-<profile>.json` from the
[v1.9.0 release assets](https://github.com/Donovoi/bstrings/releases/tag/v1.9.0) to use
`balanced` or `compact`.

## Highlights

- One user-facing executable for native strings, 51 validated patterns, OCR,
  language triage, local translation, and report generation.
- [Magika](https://github.com/google/magika)-guided file routing and
  [FLOSS](https://github.com/mandiant/flare-floss) decoded, stack, and
  tight-loop string recovery.
- CPU, DirectML, and DirectML+CPU hybrid OCR paths with CPU fallback.
- Resumable, hash-pinned acquisition and strict offline bundle verification.
- Source hashes, page/coordinate data, original and derived strings, model and
  provider identity, and explicit completion records.

## Known boundaries

- The supported baseline is Windows 11 x64 24H2 or newer. DirectML needs a
  compatible host graphics driver; CUDA is not included in the standard kit.
- `--full` does not mount filesystems or carve files from raw disk or memory
  images. Mount or carve first when filesystem-aware coverage is required.
- OCR, language detection, and translation are probabilistic. Verify important
  findings against the source evidence and untranslated parent record.
- The quality profile has an approximately 8 GB translation model. Use
  `balanced` or `compact` when transfer size or memory is constrained.
- SHA-256 files and manifests prove byte consistency, not publisher identity.
  Authenticate the GitHub release through your normal trusted process. This
  release is not described as Authenticode-signed.
- GitHub Releases contain product, installation, checksum, manifest, license,
  and release-verification assets. Raw benchmark/test evidence remains in CI or
  controlled internal evidence storage.
