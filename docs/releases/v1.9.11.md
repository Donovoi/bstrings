# bstrings v1.9.11 - Windows x64

v1.9.11 is the complete Windows x64 quality/offline release. It keeps one
installer and one Full profile while moving content classification to an early,
audited, fail-open routing stage.

## What changed

- freezes the canonical input inventory and SHA-256 manifest before content
  routing;
- classifies files with Magika in bounded multi-file batches instead of
  starting Magika once per file;
- combines Magika's raw and thresholded predictions with validated PE/PDF/image
  signatures and conservative extension hints;
- always sends every input through native byte extraction;
- hashes, calibrates, and scans the same write-denying native source handle,
  then publishes native JSONL atomically only after the trusted identity still
  agrees;
- writes atomic `content-routing.jsonl` plus exact FLOSS/OCR input projections;
- writes atomic `engine-status.jsonl` with native, FLOSS, and OCR terminal
  coverage for every routed input, including successful zero-record attempts;
- loads FLOSS, OCR, and the 7B translation runtime/model only when routed files
  or translation candidate records exist;
- reuses the validated route manifest during FLOSS recovery instead of
  classifying the file again;
- binds every FLOSS/OCR record and OCR assessment to its canonical routing
  decision while holding evidence and routing manifests immutable during use;
- records the routing manifest hash, policy, candidate counts, classifier
  errors, and conflicts in both `run.json` and `summary.json`;
- updates terminal help and user documentation for routing and percentage
  progress; and
- adds a CI-enforced Robin-round decision policy for future high-level changes,
  with independent evidence, implementation, detractor, falsifier, benchmark,
  and post-implementation reviews.

There is no file-size threshold for forensic eligibility. A large raw image
still receives complete native scanning, while file-level FLOSS and OCR require
a supplied or carved executable, image, or PDF. Unknown or failed Magika
classification cannot suppress native extraction and cannot remove a route
supported by another signal.

## Measured routing improvement

On the release workstation, 50 sanitized text files took 39.701 seconds through
the previous one-process-per-file Magika loop and 0.932 seconds in one bounded
batch: 42.62x lower wall time and 98% fewer process starts. Release acceptance
still requires unchanged forensic coverage, exact provenance, full bundle
verification, and real FLOSS/OCR smoke tests; utilization alone is not an
acceptance criterion.

## Install and run

Use the pinned, checksum-authenticated bootstrap in the
[v1.9.11 README](https://github.com/Donovoi/bstrings/blob/v1.9.11/README.md#get-started).
It safely replaces an existing physical installer file only after the new asset
matches GitHub's published SHA-256.
The authenticated release asset is `Install-BstringsQuality.ps1`.

Then run:

```powershell
.\bstrings-quality\bstrings.exe bundle verify
.\bstrings-quality\bstrings.exe analyze -d D:\evidence --full -o D:\results\case-01
```

The command reports measured percentage completion. A completed result has exit
code 0, `run.json` and `summary.json` status `complete`, and no `.incomplete`
marker.
