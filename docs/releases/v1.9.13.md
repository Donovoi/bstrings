# bstrings v1.9.13 - Windows x64

v1.9.13 is the complete Windows x64 quality/offline release. It keeps the
fresh, rollback-safe overwrite installation introduced in v1.9.12 while making
authenticated component bytes reusable across retries and later releases.

## What changed

- the installer now requires GitHub's exact published release to report
  immutable state before it trusts any release asset;
- the default `.bstrings-quality-installer-cache` is shared across release tags
  and retained after success, with release metadata kept tag-specific and large
  pack bytes stored by schema, kind, exact length, and SHA-256;
- every materialized cache object is reopened, length-checked, and fully
  SHA-256 hashed against the current trust manifest before assembly; a cache
  name, hit, timestamp, or previous successful run never authorizes bytes;
- an upgrade can seed an unchanged exact file pack from the previous physical
  installation only after the current manifest identifies the same target,
  length, and hash, and the copied object is verified again before use;
- concurrent acquisitions use private partial files and bounded physical cache
  paths, while a corrupt, missing, interrupted, linked, or stale object falls
  back to authenticated acquisition or fails closed;
- `-RemoveCacheAfterSuccess` removes only the default script-owned shared cache
  after a successful fresh overwrite. `-KeepCache` remains a compatible
  explicit spelling of the retention default, and caller-owned cache
  directories are never removed by the cleanup switch; and
- ordinary same-version changes can now batch under one release number. A
  deliberate unused forward version prepares a release, while every real tag
  still runs complete hosted bundle gates and fresh cold self-hosted acceptance.

The installer still assembles and verifies a new physical sibling directory on
every run, replaces the destination only after staged verification, verifies
the installed path again, and restores the complete previous directory if the
swap or final verification fails. No compiled bundle, smoke result, or
acceptance evidence is reused across releases.

## Install and run

Requirements: Windows 11 x64, at least 30 GiB free, and a connected staging
machine. Administrator rights are not required.

Use the pinned, checksum-authenticated bootstrap in the
[v1.9.13 README](https://github.com/Donovoi/bstrings/blob/v1.9.13/README.md#get-started).
It authenticates the immutable release and installer digest before launching
the v1.9.13 quality installer. The release asset is
`Install-BstringsQuality.ps1`.

Then run:

```powershell
.\bstrings-quality\bstrings.exe bundle verify
.\bstrings-quality\bstrings.exe analyze -d D:\evidence --full -o D:\results\case-01
```

The command reports measured percentage completion. A completed result has exit
code 0, `run.json` and `summary.json` status `complete`, and no `.incomplete`
marker. Use `-RemoveCacheAfterSuccess` only when reclaiming the verified shared
cache is more important than resuming or reusing unchanged packs later.
