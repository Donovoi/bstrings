# bstrings v1.9.14 - Windows x64

v1.9.14 is the complete Windows x64 quality/offline release. It preserves the
verified persistent cache and fresh atomic overwrite behavior from v1.9.13,
and fixes core extraction in a clean Windows PowerShell 5.1 session.

## What changed

- the quality installer explicitly loads both
  `System.IO.Compression` and `System.IO.Compression.FileSystem` before it
  constructs `ZipArchive`;
- the regression suite now verifies the required assembly-load order and
  resolves `ZipArchive` in a separate `powershell.exe -NoProfile` process;
- an existing physical `bstrings-quality` directory is still used only as a
  source of exact current-manifest file packs, then replaced by a newly
  assembled and fully verified sibling directory; and
- the persistent content-addressed cache still avoids reacquiring unchanged
  exact artifacts while fully checking their length and SHA-256 before every
  use.

The v1.9.13 destination is left intact if preflight or extraction fails. A
v1.9.14 install can therefore retry safely and reuse already authenticated
release assets and unchanged model bytes.

## Install and run

Requirements: Windows 11 x64, at least 30 GiB free, and a connected staging
machine. Administrator rights are not required.

Use the pinned, checksum-authenticated bootstrap in the
[v1.9.14 README](https://github.com/Donovoi/bstrings/blob/v1.9.14/README.md#get-started).
It authenticates the immutable release and installer digest before launching
the v1.9.14 quality installer. The release asset is
`Install-BstringsQuality.ps1`.

Then run:

```powershell
.\bstrings-quality\bstrings.exe bundle verify
.\bstrings-quality\bstrings.exe analyze -d D:\evidence --full -o D:\results\case-01
```

The installer and analysis command report measured percentage completion. A
completed analysis has exit code 0, `run.json` and `summary.json` status
`complete`, and no `.incomplete` marker. Keep the default installer cache
to resume interrupted downloads and reuse unchanged verified artifacts.
