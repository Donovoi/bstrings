# bstrings v1.9.16 - Windows x64

v1.9.16 is the complete Windows x64 quality/offline release. It prevents one
isolated translation identifier-retention error from suppressing the final
forensic report, deduplicates exact translation work across a complete
examination, and makes long translation progress and integrity outcomes visible.
Full remains the single high-recall profile.

## What changed

- hard structured identifiers now require class-specific structure or an
  independent machine signal; alphabetic hyphenation alone is advisory because
  it can be ordinary language;
- hard identifiers retain exact code points and exact occurrence counts, so a
  deleted, changed, normalized, case-changed, or surplus occurrence is rejected;
- one isolated rejected model result produces one exact-source child with
  `translationIntegrity: preservation-fallback` while the remaining candidates
  continue;
- a circuit breaker still aborts systemic degradation after more than 1%
  fallbacks among at least 100 distinct model results, or 100 consecutive
  fallbacks;
- translated children expose `verified`, `source-retained-ambiguous`, or
  `preservation-fallback` integrity. Advisory counts and fallback reasons remain
  in the attributes, and `findings.tsv` exposes the integrity status as a
  dedicated filterable column;
- a bounded in-memory hot set now fronts a run-local SQLite exact cache. An
  exact source/configuration pair is inferred once per examination while every
  parent retains one ordered child and its own provenance;
- the cache is created under the selected output, is never shared across cases,
  and is removed on normal completion and handled failure;
- translation progress now includes completed percentage, record rate, ETA,
  cache hits, distinct model inputs, and fallback count; and
- explicit `high-precision` language triage now applies effective floors of
  0.65 confidence and 0.15 target margin and reports both configured and
  effective values. Full stays `high-recall` to preserve candidate recall.

The standard quality kit still contains the accepted CPU-only llama.cpp
translation runtime. Exact deduplication can eliminate many redundant model
calls, but a large, mostly unique high-recall candidate set can still take a long
time on CPU. CUDA/hybrid translation remains a separately reviewed custom
runtime path, not a v1.9.16 release capability.

## Install and run

Requirements: Windows 11 x64, at least 30 GiB free, and a connected staging
machine. Administrator rights are not required.

Use the pinned, checksum-authenticated bootstrap in the
[v1.9.16 README](https://github.com/Donovoi/bstrings/blob/v1.9.16/README.md#get-started).
It authenticates the immutable release and installer digest before launching
`Install-BstringsQuality.ps1`. The installer assembles and verifies a fresh
sibling directory, atomically replaces an existing physical
`bstrings-quality`, and reuses unchanged cached pack bytes only after checking
their current expected length and SHA-256.

Then run:

```powershell
.\bstrings-quality\bstrings.exe bundle verify
.\bstrings-quality\bstrings.exe analyze -d D:\evidence --full -o D:\results\case-01
```

Success requires exit code 0, `run.json` and `summary.json` status `complete`,
and no `.incomplete` marker. Retain failed output for diagnosis and use a new or
empty output directory for the next attempt.
