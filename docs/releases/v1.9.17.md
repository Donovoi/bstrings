# bstrings v1.9.17 - Windows x64

v1.9.17 is the complete Windows x64 quality/offline release. It strengthens
translation integrity and failure isolation, moves Full to one smaller
Hy-MT2 7B Q4_K_M model, and adds the validated CUDA path without making users
choose between model profiles.

## What changed

- language assessments now include a compact, deterministic shadow
  translation-worthiness decision before Lingua. It distinguishes strict
  prospective whole-record structures from retain-only machine-like signals,
  remains fail-open, and does not yet remove language-detection or translation
  work; promotion requires the multilingual forensic and measured-overhead
  gates in ADR-0007;
- the shadow foundation now records bounded origin provenance plus reconciled
  routing evaluations, Lingua-eligible occurrences, actual Lingua executions,
  and reuse hits. The current router does not use origin to change a code, and
  future origin handling can only retain; no learned scorer or fuzzy bypass is
  active;
- the Python worker now atomically publishes privacy-safe schema-1 counters in
  `translation-work-stats.json`. Managed C# verifies the physical file,
  SHA-256, exact schema, and cardinalities before projecting `translationWork`
  into `run.json` and `summary.json`. `textDecisions` is a window-local first
  exact-text decision count, while `runCacheHits` exposes cross-window reuse;
- numeric-only separator sequences are not classified as ambiguous language
  identifiers, keeping bypass and cache metadata consistent. Ordinary
  alphabetic separator tokens remain advisory unless they are independently
  hard-structured;
- translation cache setup, reuse, corruption detection, batching, cleanup,
  crash paths, and atomic publication are hardened so a cache failure cannot
  publish incomplete or misleading evidence or destroy an earlier completed
  output;
- generation-limit and other rejected per-row results now produce explicit
  exact-source preservation fallbacks, participate in the existing circuit
  breaker, and allow valid sibling rows to continue;
- Full now uses the single pinned Hy-MT2 7B Q4_K_M model for both CPU and CUDA
  execution;
- `--translation-device auto` performs a real Windows sm89 CUDA preflight with
  full model load, synthetic inference, observed full-layer placement, and the
  accepted p2 schedule before processing evidence;
- an automatic CUDA preflight failure closes CUDA and selects and tests CPU
  before evidence inference, cache insertion, or translation output. Explicit
  CUDA fails closed, and the provider never changes after evidence work begins;
- the CUDA backend and redistributable closure are a separate authenticated
  pack. Already verified model and runtime objects can be reused without
  redownloading them, while every reuse still checks the current expected size
  and SHA-256; and
- progress, terminal help, provenance, and documentation now expose the
  selected translation plan, preflight/fallback behavior, layer placement,
  percentage, rate, ETA, cache activity, model calls, and preservation
  fallbacks consistently.

CUDA validation is deliberately scoped to the reviewed Windows sm89 hardware
and packaged runtime. It is not a universal CUDA compatibility claim. CPU
remains the no-GPU path; p4 and hybrid translation remain expert or experimental
boundaries rather than Full automatic behavior.

## Install and run

Requirements: Windows 11 x64, at least 30 GiB free, and a connected staging
machine. Administrator rights are not required.

Use the pinned, checksum-authenticated bootstrap in the
[v1.9.17 README](https://github.com/Donovoi/bstrings/blob/v1.9.17/README.md#get-started).
It authenticates the immutable release and installer digest before launching
`Install-BstringsQuality.ps1`. The installer assembles and verifies a fresh
sibling directory, atomically replaces an existing physical
`bstrings-quality`, and reuses unchanged cached pack bytes only after checking
their current expected length and SHA-256.

Then run:

```powershell
.\bstrings-quality\bstrings.exe bundle verify
.\bstrings-quality\bstrings.exe analyze -d D:\evidence --full -o D:\results\case-01
```

Success requires exit code 0, `run.json` and `summary.json` status `complete`,
and no `.incomplete` marker. Retain failed output for diagnosis and use a new or
empty output directory for the next attempt.
